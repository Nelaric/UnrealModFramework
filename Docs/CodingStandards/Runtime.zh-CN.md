# 运行时、性能与安全

## 并发与可靠性

- **明确关闭边界**：每项运行时服务都必须说明其生命周期与销毁顺序。一旦所属模块、`GameInstance` 或 `UWorld` 进入销毁阶段，不得再向其派发回调。
- **默认回到游戏线程**：除文档另有声明外，公开的异步回调一律在 Game Thread 执行。后台线程任务在读写仅限游戏线程访问的 UE 对象之前，必须先显式切回 Game Thread。
- **有界的外部交互**：所有外部请求或跨进程调用都必须设置明确的超时时间、有限的重试次数以及有上限的队列容量。仅对可安全重复执行的操作进行重试，在下游支持时向下传递取消请求，杜绝无限期阻塞或无上限的后台任务堆积。
- **一切外部输入均视为不可信**：`.mod` 文件头、Manifest、归档索引、Cook 元数据、远程预览消息及配置文件均属于不可信输入。必须在解析与挂载前严格限制大小与条目上限、校验规范化路径与 SHA-256 哈希，并对非法数据返回普通错误码而非触发崩溃断言。同时请注意，获准加载的原生 DLL 直接以宿主游戏进程权限执行——数字签名只能证明来源，不能提供沙箱隔离。

## 高频热点路径

- **禁止阻塞 I/O**：`Tick`、网络回调、高频 Hook 分发等热点路径严禁执行阻塞式磁盘、数据库或网络 I/O。
- **控制单帧开销**：热点路径中应避免无界内存分配、无上界循环与逐帧详细日志。耗时准备或低频重活应移至启动期或异步流程处理，并确保不破坏 UE 原生网络复制链路。
- **例外须量化说明**：若热点路径确有特殊原因需要破例，必须在 PR 中给出开销评估与明确上界。

## 控制台命令

- 本项目自定义的 Unreal 控制台命令统一以小写 `ng.` 开头，例如 `ng.perf.stat`。

## 日志、配置与密钥保护

- **日志脱敏**：严禁将访问令牌、服务器凭据、私钥密钥或玩家个人隐私写入日志；日志中只保留定位问题所需的结构化诊断字段。
- **最小化传递凭据**：通过统一的集中式服务读取和管理配置与密钥，只向各可选集成模块传递其必需的配置项，避免把密钥混入通用运行时元数据或错误提示文本。
- **权限核验与审计**：管理操作及安全敏感行为必须先完成授权校验，并在不泄露任何密钥内容的前提下留下可追溯的审计记录。
