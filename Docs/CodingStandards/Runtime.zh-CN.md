# 运行时、性能与安全

## 并发与可靠性

- 服务必须明确说明其生命周期与关闭行为。在所属模块或 World 开始销毁后，避免再向其发出回调。
- 公开异步回调默认在 Game Thread 上执行。在其他线程执行的工作访问仅限 UE 游戏线程使用的对象之前，必须显式将结果切回 Game Thread。
- 每个外部请求都必须设置明确的超时，并限制重试次数和队列增长。仅在操作可安全重复时才进行重试；下游支持取消时，应向下游传递取消请求。避免无限等待和无边界的后台任务。
- 将 `.mod` 文件头、Manifest、索引、Cooked 元数据、远程预览消息和配置均视为不可信输入。对大小与数量设定上限，在挂载前校验路径与哈希，并对无效数据返回普通错误。原生 DLL 以宿主进程权限运行；签名并不会将其沙箱化。

## 高频路径

- Tick、网络回调及其他高频路径不得执行阻塞式文件、数据库或网络 I/O。
- 避免在这些路径中进行无上限分配、无上限循环或逐帧详细日志输出。应将阻塞或低频工作移至合适的异步路径，并保持 UE 原生复制路径不受破坏。
- 确有必要的高频路径例外，必须在 PR 中说明其开销与边界。

## 控制台命令

- 项目定义的控制台命令名称必须以小写前缀 `ng.` 开头，例如性能统计命令可使用 `ng.perf.stat`。

## 日志、配置与密钥

- 严禁在日志中记录访问令牌、服务器凭据、密钥或玩家个人信息。仅记录排查问题所需的结构化诊断字段。
- 通过集中式服务读取和管理配置与密钥。仅向每个可选集成提供其必需的值，避免将密钥复制到通用运行时元数据或错误信息中。
- 管理类及安全敏感操作必须检查授权并留下恰当的审计记录，且不得记录任何密钥内容。
