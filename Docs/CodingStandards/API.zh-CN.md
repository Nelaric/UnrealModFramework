# 公开 API、错误与文档

设计接口时，请先打磨清晰、地道的 Unreal C++ 契约，再根据宿主游戏开发者或 Mod 作者的实际需求，有选择地向 Blueprint 暴露操作。跨独立原生 Mod 边界的交互统一采用版本化 C ABI，依托定宽整数类型、明确的缓冲区归属与能力协商机制。目前框架尚未冻结 1.0 稳定 API，任何契约调整都须在 PR 中写明，一旦影响二进制或协议兼容性，必须同步升级协议版本号。

## 契约与所有权

- **隔离 UE 类型与 C ABI**：面向 UE 模块的稳定接口使用标准 UE 类型；原生 C ABI 中严禁直接暴露 UE 对象内存布局或 C++ 标准库类型，应通过不透明句柄（Opaque Handle）与显式宿主函数表向原生 Mod 提供能力。
- **明确生命周期归属**：写清每项服务、句柄和缓冲区由谁创建、持有与销毁。服务实例的生命周期统一由模块或 UE Subsystem 托管；普通 C++ 对象按需使用 `TUniquePtr` 或 `TSharedPtr` 表达所有权，裸指针仅表示不持有所有权的借用；反射对象严格遵循 `UObject` 所有权与垃圾回收规则。
- **标明线程约束**：所有公开方法都必须说明允许发起调用的线程以及触发回调的线程。如无特殊说明，公开的异步回调一律在 Game Thread 上分发。
- **保护异步任务中的 UObject**：只要异步工作可能晚于目标对象销毁，就绝不能直接捕获裸 `UObject*`，请改用 `TWeakObjectPtr` 或其他生命周期受控的引用方式。

## 异步操作与错误处理

- **取消句柄与终结回调**：公开的异步操作应返回取消句柄，并支持分别传入成功、取消、超时和失败回调。调用方只需提供关心的回调；每次操作结束时有且仅有一个匹配的终结回调会被调用，未传入的回调直接跳过。
- **传递取消语义**：在下游支持取消时应向下透传取消请求，并在文档中说明当操作已完成或进入不可中止阶段时调用取消的具体行为。
- **结构化错误优先**：采用带领域错误枚举的统一结果模型。仅在需要多级分类时补充 Gameplay Tag，仅在确需辅助排障时附带说明文本，切勿用随意拼接的字符串代替结构化错误码。
- **区分断言与预期错误**：`check` 和 `ensure` 仅用于捕获代码逻辑缺陷或内部不变量被破坏。损坏的 `.mod` 清单、版本不匹配、挂载失败和外部文件 I/O 错误都属于正常的运行期外部输入异常，必须通过普通错误结果返回。

## 必需的 API 文档

如果一个类对外提供使用者接口，请将所有面向使用者的方法集中在**第一个 `public:` 区域**，紧接在类左花括号与 Unreal 反射宏（如有）之后；将仅供框架内部衔接或重写引擎生命周期的方法放在紧随其后的**第二个 `public:` 区域**，两段 `public:` 之间不得穿插 `protected:` 或 `private:`。第二个 `public:` 区域只是满足 C++ 访问权限的内部衔接点，不计入使用者 API，因此无需编写 Doxygen 注释。纯内部实现方法请放入 `protected` 或 `private`。

所有公开类型、第一个 `public:` 区域中的方法、枚举与枚举值、常量、模组扩展契约及 Blueprint 节点入口，均须使用**英文**编写 Doxygen 注释，视情况完整说明用途、参数与返回值、所有权与生命周期、线程要求，以及失败、超时与取消语义。每个公开头文件顶部都必须带有 `@file` 注释；原生 C ABI 的内存布局、版本协商、缓冲区归属和回调有效期在对外开放前也必须先写入协议规范。

具体排版要求见 [Doxygen 注释规范](Doxygen.zh-CN.md)。PR 自动检查会校验注释格式并执行零警告的 Doxygen HTML 构建，代码审查者则重点核实注释内容是否忠实反映了契约行为。
