# 公开 API、错误与文档

优先设计面向 UE 的 C++ 契约，再根据宿主游戏开发者或模组作者的需要向 Blueprint 暴露选定操作。独立原生模组的边界采用版本化 C ABI，使用固定宽度数据、明确的所有权和能力协商机制。当前尚未提供稳定的 1.0 API 承诺；契约变更必须在 PR 中说明，涉及兼容性变化时还须更新协议版本。

## 契约与所有权

- 面向 UE 的稳定接口使用 UE 类型。原生 C ABI 不得暴露 UE 对象布局或 C++ 标准库类型；按需向模组作者提供不透明句柄和明确的宿主服务。
- 明确说明每项服务、句柄和缓冲区由谁创建、持有和销毁。服务生命周期由模块或 Subsystem 管理。普通 C++ 所有权可酌情使用 `TUniquePtr` 或 `TSharedPtr`；裸指针不表示所有权。反射对象须遵循 UObject 所有权与垃圾回收规则。
- 公开方法必须说明允许的调用线程和回调线程。异步公开回调默认在 Game Thread 上执行。
- 对于可能晚于 UObject 生命周期结束的任务，不得捕获未受保护的 UObject 裸指针，而应使用弱引用或其他保障生命周期安全的机制。

## 异步操作与错误

- 异步公开操作返回取消句柄，并可分别接受成功、取消、超时和失败回调。调用方不必提供全部回调；每次操作恰会执行一个匹配的终结回调，未提供的回调不会触发调用。
- 在下游支持时应传递取消请求，并说明在任务已经完成或无法停止时取消操作的语义。
- 使用包含领域特定错误枚举的统一结果模型。仅在需要复杂分类时补充 Gameplay Tag，仅在必要时附加文本详情；不要用任意字符串替代基本错误码。
- `check` 与 `ensure` 仅用于程序错误或内部不变量。无效的模组清单、版本不兼容、挂载失败和外部 I/O 失败属于普通结果错误。

## 必需的 API 文档

暴露使用者操作的类，应将面向使用者的方法放在第一个 `public:` 区域，紧跟在类定义开头及 Unreal 反射宏（如有）之后。框架集成及 Unreal 生命周期方法则放在第二个 `public:` 区域，两段之间不得出现其他访问说明符。第二个区域仅作为 C++ 访问边界，不属于使用者 API，无需编写 Doxygen 注释。仅供实现使用的方法应保留在 `private` 或 `protected` 中。

所有公开类型、第一个 `public:` 区域中面向使用者的方法、枚举及枚举值、常量、扩展契约和 Blueprint 入口，都必须使用英文编写 Doxygen 注释，并在相关时说明用途、参数与返回值、所有权与生命周期、线程要求，以及失败、超时和取消语义。每个公开头文件都必须包含 `@file` 注释。原生 ABI 的布局、版本协商、缓冲区所有权和回调生命周期须在对外暴露前写入协议规范。

请遵循 [Doxygen 注释规范](Doxygen.zh-CN.md)。PR 检查会验证机械格式规则并构建 Doxygen HTML；审查者则需确认文档内容准确描述了实际契约。
