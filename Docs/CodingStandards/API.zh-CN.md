# 公开 API、错误与文档

先设计面向 UE 的 C++ 契约，再按宿主游戏开发者或模组作者的需要向 Blueprint 暴露选定操作。独立原生模组的边界使用版本化 C ABI、固定宽度数据、明确的所有权和能力协商。当前尚未承诺稳定的 1.0 API；契约变化必须在 PR 中说明，兼容性变化还须更新协议版本。

## 契约与所有权

- 面向 UE 的稳定接口使用 UE 类型。原生 C ABI 不暴露 UE 对象布局或 C++ 标准库类型；按需向模组作者提供不透明句柄和明确的宿主服务。
- 说明每项服务、句柄和缓冲区由谁创建、持有与销毁。模块或 Subsystem 管理服务生命周期。普通 C++ 所有权可酌情使用 `TUniquePtr` 或 `TSharedPtr`；裸指针不表示所有权。反射对象遵循 UObject 所有权与垃圾回收规则。
- 公开方法须说明允许的调用线程和回调线程。异步公开回调默认在 Game Thread 执行。
- 可能晚于 UObject 生命周期结束的任务不得捕获未受保护的 UObject 裸指针，应使用弱引用或其他安全机制。

## 异步操作与错误

- 异步公开操作返回取消句柄，可分别提供成功、取消、超时和失败回调。调用方不必提供全部回调；每次操作恰有一个匹配的终结回调执行，未提供的回调不执行。
- 在下游支持时传递取消请求，并说明工作已经完成或无法停止时取消的含义。
- 使用包含领域错误枚举的统一结果模型。仅在复杂分类需要时增加 Gameplay Tag，仅在必要时补充文本详情；不要用任意字符串代替基本错误码。
- `check` 与 `ensure` 用于程序错误或内部不变量。无效模组清单、版本不兼容、挂载失败和外部 I/O 失败属于普通结果错误。

## 必需的 API 文档

暴露使用者操作的类应将面向使用者的方法放在紧跟类开头及 Unreal 反射宏的第一个 `public:` 区域。第二个 `public:` 区域放置框架集成及 Unreal 生命周期方法，两者之间不得出现其他访问说明符。第二段只是 C++ 访问边界，不属于使用者 API，无须 Doxygen 注释。实现细节应留在 `private` 或 `protected`。

所有公开类型、第一段 `public:` 中的方法、枚举及枚举值、常量、扩展契约和 Blueprint 入口都必须有英文 Doxygen 注释。按需说明用途、参数与返回值、所有权与生命周期、线程要求及失败、超时和取消语义。每个公开头文件必须有 `@file` 注释。原生 ABI 的布局、版本协商、缓冲区所有权和回调生命周期须在暴露前写入协议规范。

遵循 [Doxygen 注释规范](Doxygen.zh-CN.md)。PR 检查验证机械格式并生成 Doxygen HTML；审查者还须确认文字与实际契约一致。
